# PokeScreen to Pokesol Converter（Gemini API 版）

ゲーム画面（「能力」「ステータス」）のスクリーンショットを、サーバー側で **Google Gemini API**
（Google AI Studio の無料枠）に渡して解析し、手動修正を経てポケソル用テキストへ変換する
Next.js (App Router) アプリです。広告枠（AdSense 用のプレースホルダー）も配置しています。

**6匹が一覧表示されたチーム画面**（「能力」一覧と「ステータス」一覧のスクリーンショット、または片方のみ）から、
最大6匹分を一括で読み取り、ポケモンごとのタブで確認・修正して、6匹分のポケソルテキストをまとめてコピーできます。
1匹だけが大きく表示された画面も引き続き使えます。

## セットアップ

```bash
npm install
cp .env.example .env.local     # GEMINI_API_KEY を記入
npm run dev                    # http://localhost:3000
```

1. <https://aistudio.google.com/apikey> で API キーを作成
2. `.env.local` に `GEMINI_API_KEY=...` を記入（`NEXT_PUBLIC_` は付けない。付けるとブラウザに公開されます）
3. 開発サーバーを再起動

Node.js 18.18 以上（20 以上推奨）が必要です。追加のSDKは不要です（REST を `fetch` で直接呼び出しています）。

## 使用モデル

既定は `gemini-3.5-flash-lite` です（無料枠・画像入力対応の軽量モデル）。`GEMINI_MODEL` で変更できます。

- 依頼にあった `gemini-1.5-flash` は、現在の Gemini API のモデル一覧になく（`gemini-2.0-flash` も
  2026年6月に終了済み）、使えません。指定するとモデル未検出エラーになります。
- 精度が足りない場合は `gemini-3.6-flash` / `gemini-3.8-flash` に変えて比べてみてください
  （いずれも無料枠がありますが、Lite より上限は低めのことがあります）。
- モデル名は Google 側で入れ替わるため、エラーが出たら
  <https://ai.google.dev/gemini-api/docs/models> で現行のモデル名を確認してください。

## 無料枠を使うときの注意

- **データの扱い**: Gemini API の無料枠に送った内容は、Google の製品改善に利用されることがあります。
  ゲーム画面だけを送る前提ですが、画面に個人情報が写り込んだ画像は送らないでください。
  有料枠に切り替えると、この扱いは変わります（最新の規約は Google のドキュメントで確認してください）。
- **上限**: 無料枠には1分あたり・1日あたりの回数上限があります。超えると「無料利用枠の上限に達しました」と表示されます。
  アプリ側のレート制限（既定: 1IPあたり10分8回）は、無料枠を使い切らないための保険としても働きます。
- **公開時**: 無料枠は動作確認・精度検証向けです。不特定多数に公開して広告で運用する段階では、有料枠への移行を検討してください。

## 出力形式（ポケソルテキスト）

```
カバルドン @ ゴツゴツメット
特性: すなおこし
能力補正: わんぱく
215(32)-132-187(32)-79-93(1)-68(1)
じしん / こおりのキバ / あくび / なまける
```

1行目は `名前 @ 持ち物`（性別が必要な種族だけ `イダイトウ(♂) @ 持ち物`）、4行目は H-A-B-C-D-S の順に「実数値(努力値)」を
ハイフンでつなぎ、努力値が0の項目は括弧を省略します。複数匹は空行1つで区切ります。
レベルとテラスタイプは出力しません。項目が足りない場合はその行を出力せず、画面に警告を表示します。

## 1匹ずつの画面からの読み取り（単体モード）

画面左上の切り替え「チーム画面（2枚）／1匹ずつ（最大6枚）」で、読み取る画面の種類を選べます（画像はモードごとに別々に保持）。

- **1匹ずつ**: ポケモン1匹の詳細画面（実数値・能力ポイント・技・特性・「能力補正」が1画面に出る画面）を、1匹1枚、最大6枚まとめて送ります。
  6枚を1回のAI呼び出しで送るため、画像はクライアントで長辺1280px・約0.6MBに圧縮します（合計がサーバーの上限4MBに収まる設定。`lib/image.ts` の `SINGLE_SHOT_COMPRESS`）。
  AIへの指示は単体用（`lib/ai.ts` の `SINGLE_SYSTEM_PROMPT`）で、種族名は下段の「No.000 種族名」から読み、上段のニックネームは使いません。性格は「能力補正」に書かれた名前を使います。
- **持ち物**は画面に出ません。メガシンカ後の姿（「メガガブリアスZ」など）が表示されているポケモンだけ、対応するメガストーン（ガブリアスナイトZ）を自動で入れます。それ以外は空欄で、候補から選べます。
- **メガシンカ後の姿が表示されている画面**は、実数値も特性もメガシンカ後の値です（チーム画面はメガ前の値）。実数値の照合はメガ後の種族値で行います。
  出力に必要な「元の特性」は画面から分からないため、元の特性が1つだけのポケモンはそれを入れ、複数あるポケモンは特性欄を空にして、選ぶよう案内します。
- チーム画面と同じ確認・修正欄、出力、各種補正（技名・持ち物・ニックネーム）がそのまま使えます。

## チーム画面（6匹）の読み取りについて

- 画像2枚（能力・ステータス）を1回のAI呼び出しで渡し、タイル番号（1〜6）が同じポケモンを統合して返させています。
  並び順はタイル番号順です。
- **性格**はステータス画面の能力名の横にある赤↑（1.1倍）・青↓（0.9倍）アイコンから判定します。
  AIには5能力（こうげき・ぼうぎょ・とくこう・とくぼう・すばやさ）を1つずつ `up`/`down`/`none` で答えさせ、
  あわせて性格名も返させます（`lib/ai.ts` のプロンプトに全20性格の対応表を、`NATURES` から自動生成して載せています）。
  コード側（`decideNature` in `lib/extract.ts`）の決定ルールは次のとおりです。
  1. ↑が1つ・↓が1つ読めた → 対応表で決定（AIの性格名より優先）
  2. 5能力すべて「印なし」と読めた → 「がんばりや」（補正なし）
  3. AIの性格名が、読めた印と矛盾しない → その性格名
  4. それ以外 → **空欄**（読めていないのに「補正なし」とは決めません。黄色の枠で手入力を促します）
- **性別・姿違い**（`lib/species.ts`）:
  - 性別は、性別で姿・特性・技が変わる種族（`GENDER_MATTERS`: イダイトウ・ニャオニクス・イエッサン・パフュートン）だけ、
    `イダイトウ(♂) @ 持ち物` の形（スペースなし）で出力します。それ以外（ガブリアス等）は、画面に性別アイコンがあっても出力しません。
    種族を足すときは `GENDER_MATTERS` に基本の名前を追加してください。
  - 姿違いは `ゾロアーク(ヒスイ) @ ふうせん` の形です。AIが「ヒスイのすがた ゾロアーク」などと返しても、コードが `ゾロアーク(ヒスイ)` にそろえます。
- **メガシンカ**（`lib/mega.ts`）: メガストーン持ちは、メガシンカ後の名前と特性に変換します
  （`メガリザードンX @ リザードナイトX` / `特性: かたいツメ(もうか)`）。特性表は81体分で、別の情報源との全件照合済みです。
  性別が必要なメガ種族は、括弧なしで `メガニャオニクス♂ @ ニャオニクスナイト`（特性は `トレース(いたずらごころ)` のように元の特性が括弧内に入る）。
  表に無いメガシンカは、画面の名前・特性のまま出力します。新しいメガシンカは `MEGA_ABILITIES` に1行足してください。
- **確認・修正欄（ポケソルの編集画面とほぼ同じ）**（`app/components/PokemonFormFields.tsx`）:
  ポケモン → 技（技名の右にタイプのバッジ）→ 特性 → 持ち物 → 能力補正（性格）→ 能力ポイント の順です。
  能力ポイントは H・A・B・C・D・S ごとにスライダー・＋－・数値入力・MIN/MAX で調整でき、右上に「残 n / 66」と「全リセット」があります。
  実数値は、種族値・能力ポイント・性格から自動で計算します（`lib/calc.ts`。Lv50・個体値31、HP＝種族値+75+ポイント、
  HP以外＝(種族値+20+ポイント)×性格補正の切り捨て。ポケソルの画面の数値と一致することを確認済み）。
  - 種族値などのデータは `lib/pokedex.ts`（チャンピオンズで使える345種）、技のタイプは `lib/data/moves.ts`（511技）にあります。
    新しいポケモンや技が増えたら、そこに1行足してください。表に無い種族は、実数値を手入力できます。
  - イダイトウ・イエッサンなど性別で種族値が違うポケモンは、性別を選ぶと種族データを読み込みます。
  - メガストーンを持たせると、メガシンカ後の種族値で計算します（画面の実数値はメガシンカ前の値なので、読み取り結果の照合はメガ前の種族値で行います）。
- **名前の読み違いの自動補正**（`lib/snap.ts` / `lib/calc.ts` の `snapExtracted`）: AIが画像から読み取った技・特性・ポケモン名の
  1文字の読み違い（例: 「うたたたのアリア」→「うたかたのアリア」）を、既知の名前表への最近傍マッチで直します。
  **APIは呼ばないので、トークン消費は増えません。** 技は511技の表、特性はそのポケモンの特性、ポケモン名は345種の一覧が対象です。
  表に完全一致する名前は直さず、近い候補が1つに絞れない・近すぎない場合は、読み取った文字のまま残します。
  直した内容は、解析後のお知らせに「名前の読み違いを自動で直しました: …」と表示されます。
  表に無い技・特性は補正できないので、`lib/data/moves.ts` と `lib/pokedex.ts` に足してください。
- **候補から選べる入力欄**（`app/components/Combobox.tsx`）: ポケモン名・技・特性・持ち物は、入力すると候補が絞り込まれ、選ぶと入ります（↑↓・Enter・クリック対応）。
  - ポケモン: チャンピオンズで使える種族（タイプのバッジ付き）。「メガ」と入力するとメガシンカ後も出ます。
  - 技: そのポケモンが覚える技だけ（`lib/data/learnsets.ts`。メガシンカ後は元の姿、イダイトウなど性別で分かれるものは性別を選ぶと絞り込み）。他の枠で選んだ技は除きます。覚える技の一覧にない技が入っていると、黄色の注意と出力前の警告が出ます。
  - 特性: そのポケモンの特性（メガストーン持ちはメガシンカ前の特性）。
  - 持ち物: 持ち物の表（`lib/itemNames.ts`）。そのポケモンのメガストーンが先頭に出ます。
  - 候補にない文字も入力できます（AIが読み取った名前をそのまま残すため）。技の表記補正は、覚える技の中からいちばん近い技を先に探します。
  - 覚える技のデータの出典: Pokémon Showdown の Champions 用データ（smogon/pokemon-showdown の `data/mods/champions/learnsets.ts` と日本語名）を2026-10に取り込み、282種の全技がこのアプリの技表に対応づくことを確認済みです。ゲームの更新で変わったら `lib/data/learnsets.ts` を更新してください。
- **持ち物の表記**（`lib/itemNames.ts`）: 持ち物はチャンピオンズの表記で出力します。AIの読み違い（「カイリュウナイト」→「カイリュナイト」）は、
  持ち物の表（メガストーン約60種＋主要な持ち物約75種）への照合で直します（APIは呼びません）。メガストーンは種族名の先頭2文字が合う中から、2文字違いまで・X/Y/Zの付き方が同じものだけ。
  その他の持ち物は1文字違いまで・同じ近さの候補が複数なら直しません。表に無い持ち物はそのまま出力します（`ITEMS` に1行足してください）。直した内容は解析後のお知らせに出ます。
- **ニックネーム付きの画面**（`identifySpecies` in `lib/calc.ts`）: タイル見出しがニックネームでも種族を特定します。AIには種族名を絵・タイプ・特性から答えさせ（プロンプト1文）、
  さらにコード側で、読み取った特性と実数値（能力ポイント・性格を考慮）に合う種族が1つに決まれば、その名前に置き換えます（APIは追加で呼びません）。
  名前が正しく特性・実数値とも合っていれば触りません。特定できないときは「ポケモン名を選んでください」と表示します。変更は解析後のお知らせに出ます。
- **技名の表記**（`lib/moveNames.ts`）: 技はポケモンチャンピオンズの表記（ひらがな・カタカナ）で出力します。AIが漢字（「不意打ち」）や
  かな＋漢字の崩れ（「ふ不意打ち」）で返しても「ふいうち」に直し、手入力の漢字名も出力時に直します。漢字→かなの対応は `MOVE_ALIASES`、
  表に無い技名はそのまま出力します。プロンプトにも「漢字に直さない」と1文足しました（トークン増はごくわずか）。
- 数字・英字を含む技は、ゲームの表記どおり全角です（「１０まんボルト」「１０まんばりき」「３ぼんのや」「ＤＤラリアット」「Ｇのちから」。Showdown の日本語データとも一致）。半角で来ても全角に直します。
  かな／カタカナの違い、長音のハイフン・ダッシュ、「力」「夕」などかなに似た漢字も、技の表の表記に直ります（全511技×表記ゆれ約1,600通りで検証済み）。
- （参考）技名の「１０まんボルト」は、ゲームの表記どおり数字が全角です（ポケソルに反映されるのはこの表記）。AIや手入力が半角の「10まんボルト」でも、出力は全角にそろえます。
- **ロトムのフォルム**: ポケソルの表記は `ロトム`（通常）・`ロトム(炎)`・`ロトム(水)`・`ロトム(氷)`・`ロトム(飛)`・`ロトム(草)` です（ヒートロトム／ロトム(ウォッシュ) などの表記ゆれもこの形に直します）。
  画面の名前は常に「ロトム」なので、AIにはタイプアイコンから姿を答えさせ（プロンプト1文＋`types`項目）、コード側でも、特性・実数値・タイプ・覚える技（ハイドロポンプ→水 など）から姿を特定します。
  フォルムごとの種族値・覚える技・出力は、参考ポケソルテキスト6匹分で1文字も違わず再現できることを確認済みです。
- **テラスタイプ**: 名前の横に並ぶアイコンは種族のタイプなので、テラスタイプとしては読み取りません。
  テラスタイプの表示がある画面でだけ入ります（無ければ空欄）。
- **努力値**は画面に表示された数値をそのまま入れます（換算はしません）。
  値は 0〜32、1匹の合計は66までで、ポケソルの参考フォーマットも同じ数値です。
- 6匹分は出力が長いため、解析に20〜40秒ほどかかることがあります。小さな数値の読み取り精度が足りない場合は、
  `GEMINI_MODEL` を `gemini-3.6-flash` などに変えて比べてください。

## エラー表示の対応

| 状況 | ユーザーに表示される内容 |
| --- | --- |
| APIキー無効・期限切れ・漏えい判定・権限なし | AIサービスの認証に失敗（管理者に連絡） |
| モデル名が存在しない（404） | 設定されたAIモデルが見つからない（`GEMINI_MODEL` の修正を促す） |
| 無料枠の上限超過（429） | 無料利用枠の上限に達した。しばらく待って再試行 |
| 過負荷（503） | 混み合っている。1回自動で再試行し、だめなら再試行を促す |
| 安全フィルターによるブロック | 画像を処理できなかった。別の画像か手入力を促す |
| 無料枠の地域制限 | このサーバーの地域では無料枠を使えない可能性 |
| 出力の打ち切り・JSON不正 | 応答を解釈できなかった。再試行を促す |

APIキーは、エラーメッセージやログに出ないようにしています（キーはURLに含めず、HTTPヘッダーでのみ送信）。

## デプロイ（Vercel）

GitHub に push して Import し、Environment Variables に `.env.example` の項目を登録してください。
`GEMINI_API_KEY` はサーバー側でのみ読み込まれ、ブラウザには出ません。

## 広告（AdSense）

`NEXT_PUBLIC_ADSENSE_CLIENT` とスロットID（`NEXT_PUBLIC_ADSENSE_SLOT_SIDEBAR` / `_FOOTER`）を設定すると、
広告枠が実際の広告に切り替わります。未設定の間はプレースホルダーです。広告を出すサイトにはプライバシーポリシーが必要です
（画像をGoogleのAPIへ送信する点も明記してください）。

## 乱用対策

同一オリジン以外の拒否、画像の形式・サイズ検証、IPごとの回数制限と1日の総量制限を実装しています。
ただしレート制限はメモリ内のベストエフォートで、サーバーレス環境では厳密な上限になりません。
公開する場合は Upstash Redis や Vercel WAF への置き換えを検討してください。

## カスタマイズ

- **抽出の精度・項目**: `lib/ai.ts` の `SYSTEM_PROMPT` を編集（項目を増やす場合は `lib/extract.ts` の `sanitizeAiResult` も更新）
- **出力フォーマット**: `lib/pokesol.ts` の `buildPokesolText`（取り込み仕様が変わったらこの関数だけを直します）
